# 程序生成结构化工具摘要：2026-09-30

## 改动与目的

保留现有 ReAct 工具调用流程，用程序把 `rag_query` 和 `rag_summarize` 的 SQL 结果转换成紧凑 JSON，不增加一次模型调用。目标是控制工具结果占用的上下文，并保留可核对的金额、筛选条件和来源。此次没有压缩对话历史，也没有更改 SQLite Memory。

明细使用 `columns` + `rows` 表格表示，保留行 ID、文档 ID、文件名及原有业务字段。最多展示 20 行，返回匹配行数、展示行数和省略行数；明细样本不能用于计算全量总额。需要完整统计时使用 `rag_summarize`，需要更多明细时缩小筛选范围。目前没有分页接口。

统计先计算所有匹配分组的总行数、总数量和总金额，再展示最多 20 个分组。输出包含总分组数、省略分组数，以及来源表 `ocr_rows`、确认状态和筛选条件。省略分组不会从总额中扣除，但被省略分组的具体数值不在输出中。

## 配对评估

临时 SQLite 数据库中生成 400 条已确认的 2024 年销售记录：40 个商品各 10 条，每条数量 1、金额 10，总金额 4,000。另加入 2025 年已确认记录和 2024 年待确认记录，检查年份和确认状态排除规则。前后使用相同数据和真实 SQL 查询工具，不调用 DeepSeek 或 OCR。

指标为工具输出文本使用 `cl100k_base` 编码的代理 token 数，不能当作 DeepSeek 实际 token 或费用。工具定义、系统提示和对话历史不包含在该指标中。

| 场景 | 改动前 | 改动后 | 减少 | 减少比例 |
| --- | ---: | ---: | ---: | ---: |
| 默认 20 行明细 | 1,061 | 922 | 139 | 13.10% |
| 请求 400 行明细 | 20,821 | 922 | 19,899 | 95.57% |
| 40 个分组统计 | 932 | 395 | 537 | 57.62% |

大明细输出展示 20 行并明确省略 380 行；分组输出展示 20 个分组并明确省略 20 个分组，但保留全部 400 行的总额 4,000。大幅下降主要来自减少展示数据，不代表保留所有明细的无损压缩。默认明细字符数从 1,705 增至 2,040，代理 token 仍下降；字符数与 token 数不能互相替代。

评估脚本断言新输出中的年份、确认状态、来源、明细金额、匹配/省略数量和全量统计值。自动测试共 20 项通过；其中新增两项验证明细来源和省略标记，以及省略分组后全量金额不丢失、其他年份不混入。

## 尚未测量的影响

本次没有测量真实模型回答正确率、延迟、实际 token 或 API 成本。工具描述也有更新，其输入开销尚未纳入比较。行数上限不是严格 token 上限，单个字段过长时输出仍可能很大；其他工具输出也未处理。

下一步可用少量真实 DeepSeek 合成任务检查：明细样本是否被误当作全量、统计金额和年份是否回答正确、能否遵循省略标记继续查询。记录模型实际用量和耗时后，再决定是否加入字符/token 预算、字段限长和对话摘要。
