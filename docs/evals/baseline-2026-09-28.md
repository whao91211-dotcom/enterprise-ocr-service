# Agent 优化前基线（2026-09-28）

这份基线在聊天接口修复后的 `feat/agent-v2` 上建立。目的是分开观察上下文传递、真实模型任务表现与尚不可测的 OCR；后续 Memory 改动应使用同一批用例复测。

## 1. 离线上下文可用性

运行 `python evals/memory_context_baseline.py`。脚本通过真实 FastAPI 路由发送请求，在 Agent 边界用固定替身读取收到的消息；不调用 DeepSeek 或 OCR。[原始结果](2026-09-28-memory-context-baseline.json)。

| 固定场景 | 必要上下文到达 Agent | 观察 |
|---|---:|---|
| 文字追问，浏览器随请求传入历史 | 是 | 当前请求和上一轮历史均收到 |
| 图片追问，浏览器随请求传入历史 | 是 | 图片、当前文字和上一轮历史均收到 |
| 页面重开后继续，客户端不再传历史 | 否 | 服务端没有会话标识与持久化历史 |

**结果：3 个固定场景中 2 个具备必要上下文。** 这是输入可用性检查，不是 Agent 回答正确率，也不是随机样本上的成功率。页面重开场景缺失上下文是下一阶段会话 Memory 的基线。

## 2. 真实 DeepSeek 文本诊断

运行 `python evals/real_text_baseline.py`。脚本在临时 SQLite 数据库写入并确认三条合成记录：2024 年甲公司 100、2024 年乙公司 200、2025 年乙公司 900。仅对文字问题调用当前 `run_agent_events` 与 DeepSeek；不访问 OCR。程序只测每个问题执行期间的耗时，不包含进程启动和依赖导入时间。[原始工具轨迹与回答](2026-09-28-live-text-baseline.json)。

| 问题 | 期望金额 | 观察到的关键工具参数 | 最终回答 | 耗时 |
|---|---:|---|---:|---:|
| 统计 2024 年甲公司的销售额 | 100 | `rag_summarize(keyword=甲公司, year=2024)`；另查一次明细 | 100 | 8.634 秒 |
| 那乙公司呢？（接上轮） | 200 | `rag_summarize(keyword=乙公司, year=2024)` | 200 | 2.052 秒 |
| 2024 年总销售额是多少？ | 300 | `rag_summarize(year=2024)` | 300 | 2.102 秒 |

三个问题的工具结果和最终回答均符合这批合成数据的期望；第二题正确继承了年份，未计入乙公司 2025 年的 900。**这是 3 个诊断样例的观察，不代表总体准确率。** 第一题调用了两个工具，另外两题各调用一个。样本量不足以报告有代表性的 P50/P95 延迟。

## 3. 当前缺口与复测规则

- OCR 服务已中断；字段准确率、完整单据正确率以及含真实图片的端到端任务成功率均未测量。
- 当前事件流不暴露模型 token 使用量；本次未测调用成本。
- 会话历史仍由浏览器传入。真实模型的多轮成功案例证明“有历史时可利用”，不能证明刷新后可续聊。
- 后续加入服务端 Memory 后，保持这三条合成记录和三个问题不变，分别复测上下文可用性、工具参数、答案和逐题耗时。增加更多样例后，再计算整体成功率与延迟分布。
