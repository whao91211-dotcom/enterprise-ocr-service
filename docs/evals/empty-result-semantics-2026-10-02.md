# 无匹配金额口径与截断后澄清：2026-10-02

## 问题与最小修正

固定known-gap-v1基线中的无匹配例，工具只返回没有符合条件的已确认数据，但模型自行回答销售额为0。问题位于回答语义：系统业务规则尚未明确区分无记录与有记录且金额为0，而不是SQLite统计函数生成了错误金额。

在共享FIELD_RULES补4句：无匹配只说明没有匹配的已确认记录，无法确认实际销售额；反复追问不能自行补零；仅当匹配记录的工具统计明确给出0时允许报告零；不能无依据猜测字段缺失、折扣等原因。共享规则进入现有流式链路及旧版系统提示，但本次真实模型验证仅覆盖HTTP流式链路。

首次完整复测修正了无匹配与零金额解释，却在截断含糊追问例中直接使用成功快照年份2024查询乙公司200。该例在初始基线曾正确澄清，因此不能由单次变化断言提示改动导致回退；它揭示现有依赖模型判断的行为不稳定。

随后只在既有成功查询状态提示中补明确限制：成功快照不包含无匹配查询条件；用户继续无匹配查询但近期缺少年份时，必须先询问，不能用成功快照年份执行。没有新增状态表、强制工具参数或解析用户意图的硬编码。未修改工具格式、查询逻辑或数据。

46项单元测试通过，已有2个配置/弃用警告。原评分器用例继续验证无匹配不补零、允许否定零断言、澄清而不执行猜测，以及最新结果必须有新工具与正确工具总额。没有添加仅复述提示内容的单元测试。
