# 业务字段语义修正：2026-10-02

## 问题与改动

此前三条真实合成任务中，两条回答把 `amount` 标为“合计金额”，但该字段实际表示数量。金额 `sum` 和筛选年份的数值虽然正确，字段标签仍是业务错误。

保留数据库字段及工具键名，新增共享字段词典并用于两个聊天入口的系统规则。SQL 明细和统计 JSON 增加 `field_meanings`，明确：

- amount / total_amount：数量 / 数量合计。
- sum / total_sum，以及聚合行中的 total：票面金额 / 金额合计。
- total_rows 和分组 rows：明细行数，不能替换为单据数。
- 不用数量乘单价覆盖实际票面金额，不推断未提供的币种。

数据库数据和聚合计算未改动，统计保留全量总额。新词典只解释返回值，不做答案后处理或强行替换模型文字。

## 真实模型配对诊断

复用三条合成记录、相同三个问题和相同评估模型配置（deepseek-chat，temperature=0.3，SDK timeout=20秒，max_retries=0）。没有发送真实发票图片或校对数据。

| 指标 | 修正前 | 修正后 |
| --- | ---: | ---: |
| 没有数量误标为金额的回答 | 1/3 | 3/3 |
| 销售额与年份符合预期 | 3/3 | 3/3 |

无数量误标的回答增加两条；这只是每例一次的小样本观察，不能当作代表性准确率提升。逐例人工查看修正后回答，数量、票面金额和明细行数标签符合工具结果。耗时7.810、2.130、1.727秒，不据此声称稳定延迟变化。实际 API token 和费用未测量。

诊断脚本新增已知字段误标检测，检查同一表格单元/短句中 `amount` 或 `total_amount` 被称为金额的情况。该规则不是通用模型裁判：不含英文字段名的误标、复杂跨句解释等仍需人工核查，不把未命中规则当成所有字段正确。
