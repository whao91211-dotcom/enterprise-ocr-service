# SQLite 显式长期偏好第一版（2026-09-28）

主聊天页支持三种固定指令：`记住：内容`、`忘记：原内容`、`查看记忆`。只有第一种指令会写入 SQLite；普通聊天即使提到某种偏好，也只保存在当前会话的短期历史里。记忆指令由后端直接解析和执行，不让模型决定是否写入。每条偏好最多 200 字，一个档案最多 20 条；删除时按原文完全匹配，重复保存不新增记录。修改偏好需要先忘记旧内容，再记住新内容。

浏览器保存独立于会话 ID 的随机档案 ID。“新对话”只更换会话 ID，因此同一浏览器的新对话仍可读取偏好。普通提问会把该档案的偏好传给现有 ReAct Agent，用于回答方式和默认选项；提示词规定数据真实性和工具规则仍优先，当次用户要求与旧偏好冲突时，以当次要求为准。记忆指令不进入 Agent 对话历史，以免删除偏好后旧指令继续影响模型；刷新页面后可通过“查看记忆”确认当前状态。

选择 SQLite 是因为当前偏好数量少、可按档案 ID 精确读取，不需要向量检索或 RAG。当前只有浏览器持有的随机 ID，没有登录认证；它适合单用户演示，部署给多个用户前需要账号身份和访问控制。浏览器存储被清除后，旧档案 ID 无法自动找回。

本次新增 5 个接口测试，用临时 SQLite 和替身 Agent 验证了显式保存跨新会话可读、普通消息不写入、查看及删除、档案隔离，以及固定指令在模型不可用时仍可执行。完整测试 18/18 通过；原项目没有跨会话偏好能力，也没有该指标的改动前可比测量，不能把测试通过数解读成回答质量的提升。短期记忆原有的 3 个固定离线场景仍是 3/3。真实模型的偏好遵循和额外延迟需单独测量。OCR 服务仍不可用。

已提供 `python evals/real_preference_probe.py`，用同一个合成问题比较有无格式偏好时的 DeepSeek 回答和耗时。本次尝试在超过两分钟后仍未产生结果，已中止；**没有可报告的真实模型前后结果**。该脚本不读取企业数据，也不调用 OCR。

本版只接入主聊天页使用的 `/api/agent/chat` 和上传端点；旧的 `/api/agent` 接口还没有档案 ID 参数。后续若继续保留旧接口，再统一两套调用路径。
