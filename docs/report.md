# 项目报告：基于 InternVL3 微调模型的企业文档处理多智能体框架

> 四人团队 · 课程项目 · 本报告聚焦"销售单据识别 + 智能体问答"完整闭环的实现与效果

## 1. 项目目标

- **基本目标**：单据类文档的智能处理和问答 —— 搭建 Chatbot 系统，
  能处理企业文档并转化为结构化信息、解析用户意图、针对性回答提问。
- **拓展目标**：扩展到其他类目文档，通过意图识别有效分配任务（多 Tool）。

## 2. 技术架构

```
                    ┌────────────────────────────────────┐
                    │  Chatbot 前端(网页 /api/chat/stream) │  ← SSE 流式
                    └──────────────────┬─────────────────┘
                                       │
                    ┌──────────────────▼─────────────────┐
                    │  智能体中控 rag/agent.py            │
                    │  ChatDeepSeek(deepseek-chat)       │
                    │  意图识别(规则+LLM) + function-call │
                    └───┬──────────────┬──────────────┬──┘
        ┌───────────────▼───┐  ┌──────▼──────┐  ┌────▼────────┐
        │ Tool1 OCR 识别     │  │ Tool2 RAG   │  │ Tool3 索引  │
        │ InternVL3→8列CSV   │  │ 查询已确认   │  │ 刷新        │
        └───────┬───────────┘  │ 数据(BM25)  │  └─────────────┘
                │              └──────┬──────┘
   ┌────────────▼─────────────┐  ┌───▼───────────────┐
   │ OCR 服务(app 8000)       │  │ all_sales.csv      │
   │ 识别/清洗/确认/防覆盖      │  │ 状态列 人工终稿      │
   └──────────────────────────┘  └────────────────────┘
```

**分层**：OCR 数据服务（数据生产+质检）与智能体（理解+路由+回答）解耦；
Tool 注册表 `TOOL_REGISTRY` 支持横向扩展新文档类目。

## 3. 关键实验与结论

### 3.1 InternVL3 识别契约探索（S0/S1）
- 训练标注为 8 列：desc,date,from,item,amount,price,tax,sum（顾客公司/发注日/源公司/项目/数量/单价/税率/金额）
- 纯英文 key prompt（`desc,date,from...`）会把 **from 列错认成幻觉日期**
  （实测输出 `2022年03月22日`）；改为**中英语义引导**
  `from(发货公司/源公司)` 后 from 正确识别为 `菱洋電子貿易(上海)有限公司` ✓
- 训练同款长 prompt 会使 llama.cpp 单槽 9052 读超时卡死 → 使用折中 `cols8` 模式

### 3.2 清洗规则
date 归一 `YYYY年MM月DD日`；amount 取整；price/sum 去 ¥/千分位、两位小数。

### 3.3 数据质量保障（人工确认）
- 识别写入 → 状态=待确认 → 人工核对(Excel/API confirm) → 已确认
- **RAG 只消费已确认行**（模型有幻觉/重复行，草稿不可直接入库）
- 已确认图防重识别覆盖（force 才可强制）

### 3.4 检索与问答
- BM25 中文检索（纯 Python 二元组），索引 27 条已确认文档
- DeepSeek function-calling 自动路由；规则意图识别作引导（5 类问题分类实测全对）

## 4. 效果（真实端到端联调记录）
